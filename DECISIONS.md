### Why Ritz for B2
Independent, plain HTML, dated URLs, stable session ids, permissive robots. Exercises the HTML-fixture + parser pattern. Hoyts is easier but is a JSON client — do it first in B5.

### B5 order (revised after P4)
Hoyts (API) → **Palace (`__NEXT_DATA__`)** → Orpheum (API) → Golden Age → Roseville (Veezi) → Event (print view) → Reading (from AU IP) → Moonlight (summer).

Three of the big sources (Hoyts, Palace, Orpheum) are Vista-backed with `HO000…` movie ids — worth a shared `vista_movie_id` field in models.py for cross-venue film matching before TMDB.

- **Palace buildId:** `_next/data` route breaks on each deploy — scrape the HTML page and parse the `__NEXT_DATA__` tag rather than hard-coding buildId.

- **Palace times are not UTC (from B5b):** the P4 row and B5b say Palace `date` is UTC. It ends in "Z", but Palace's own site strips the "Z" and reads it as local time, and the hours only make sense that way (10:00–21:00 local; as UTC they'd be 21:00–08:00). B5b treats it as Sydney wall-clock time. Confirm by checking one session on palacecinemas.com.au.
- **Palace today missing (from B5b):** on 2026-10-18 (Sun, ~14:00) all three Palace pages listed sessions from Monday 19th onwards — none for today. If the page never includes today, the 03:00 nightly run (B6) will miss each day's Palace sessions. Recheck at another time of day before B6.
- **Vista ids are per chain (from B5b):** the note above ("worth a shared `vista_movie_id` … for cross-venue film matching") doesn't hold — the same film has different ids at Hoyts and Palace, and Palace's HO00011213 (The Thing) is a different Hoyts film. The TMDB cache key is now `vista:<chain>:<id>`; films are matched across chains by TMDB id instead.
